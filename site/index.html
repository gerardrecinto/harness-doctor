harness-doctor checks Harness, GitHub Actions and Jenkins pipeline files for risky settings, like a password written in the file or a deploy to prod with no approval. It shows the line and the fix.

Quick start

Needs Python 3.10 or newer. This installs the current main branch.

python -m venv .venv && . .venv/bin/activate
pip install "harness-doctor[schema] @ git+https://github.com/gerardrecinto/harness-doctor"
harness-doctor check .harness .github/workflows
harness-doctor check .harness --fail-on warning
harness-doctor check .harness --format sarif
harness-doctor explain HD007

The last two commands save a report file that GitHub can read (SARIF) and explain one rule.

Exit code 0 means clean, 1 means findings, 2 means bad input such as a missing folder.

- uses: actions/checkout@v7
- uses: gerardrecinto/harness-doctor@v0.1.1
  with:
    path: .harness
    fail-on: warning
    schema: "true"

This runs the check automatically on every pull request.

The Action puts findings on the pull request. The Actions and Jenkins rules are on main but not in v0.1.1, so v0.1.1 checks Harness files only. A pre-commit hook is in the README.

What this does not do
  • It is a linter. It shows these patterns are absent, not that a pipeline is safe.
  • It reads one file at a time. It does not resolve templates, runtime inputs or account policy, and does not know which secrets exist.
  • Jenkins checks read the Groovy text, so a dynamically built pipeline can hide a finding.
  • A secret that does not look like one by name or format is not flagged.
